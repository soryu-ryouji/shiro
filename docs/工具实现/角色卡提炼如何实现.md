# 拆书·角色卡提炼：工作流实现规范

本文档定义拆书流水线第 1 阶段「角色卡提炼」的实现规范：从外部导入的剧本（或小说）生成目录形态的角色档案包。上游第 0 阶段「切块」见 [自动拆书如何实现](./自动拆书如何实现.md)。实现者按本文档直接编码。

## 1. 定位与边界

- 职责：外部文本 → 角色档案包草稿 → 人工确认 → 写入项目 `设定/人物/<名字>/`
- 产物是**还原型深卡**：保留原作专名与引文，面向同人/改编写作的完整还原。泛化为全局库原型（去专名、提炼可迁移层）是独立的后续步骤，本规范只预留衔接（见 §10）
- 人工确认点两个：角色清点后（§5.2）、逐角色成卡后（§5.7），其余环节自动推进
- 不做：世界观设定拆解、套路提取——同属拆书流水线，另立规范
- 设计前提：**论断必须钉在证据上，引文必须回查原文**。引文无法在原文定位的，删除并显式标注，不静默保留；「好卡」的判据是论断鲜明且全部可回溯，不是模板槽位填满

## 2. 总流程

```text
外部文本导入
  │
  ▼
structure-probe ── 素材形态与引用粒度判定（确定性，§3）
  │
  ▼
chunk ─────────── 切块（复用 stage 0 规范）
  │
  ▼
选择闸门 ──────── 弹窗列出段清单（label + 字数 + 开头预览），命中角色名的段标绿；快选：全选 / 全不选 / 只选名称段；不设段数上限。任务详情提供「复制为新制作」（回填原填写信息，改完再跑）
  │
  ▼
segment-notes ─── 逐段结构化笔记（map，LLM·性价比档；只跑选中段）
  │
  ▼
character-census ─ 角色清点与分层（确定性统计 + LLM 判定）
  │
  ★ 人工确认点 1：别名归并、深卡名单
  │
  ▼
evidence-pack ─── 逐角色证据汇编（确定性为主）× N 角色
  │
  ▼
生成节点组 ────── soul → speech / behavior / relationship / events
  │                → limit → index（LLM·强模型档，逐角色一条子管线）
  ▼
quote-verify ──── 引文与引用回查（确定性，§5.6）
  │
  ▼
cross-review ──── 卡内一致性与角色间对偶审核（LLM·审核档）
  │
  ★ 人工确认点 2：逐角色成卡确认 → 写入 设定/人物/<名字>/
```

## 3. 素材探测与引用粒度

### 3.1 素材形态判定（structure-probe，确定性）

```ts
type SourceForm = "script" | "prose";
// script：台词有显式归属结构，台词抽取走确定性路径
// prose：无归属结构（小说等），对白识别退化为笔记阶段 LLM 处理
```

- 台词归属模式（`ATTRIBUTION_PATTERNS`，有序、只追加）：
  1. `^【?名字】?\s*[：:]台词`（名字+冒号引导）
  2. 名字独行（trim 后 ≤ 12 字符且不含标点）且下一非空行为台词
- 判定：抽样前 `ATTRIBUTION_SAMPLE_LINES(1000)` 行，命中 ≥ `ATTRIBUTION_HIT_RATIO(0.6)` → `script`
- 同一探测过程输出**引用单元表**：全文章节/场次标题的有序列表（含切块段 label 与段内场次）

### 3.2 引用粒度决策表

不同素材的最小稳定标题层级不同，引用单元随之自适应：

| 素材结构               | 引用单元                     | 卡内示例              |
| ---------------------- | ---------------------------- | --------------------- |
| 剧本·场次编号          | 段内场次                     | 「ぱん。」（第81场）  |
| 剧本·集数+场           | 集·场                        | 「……」（第3集·第5场） |
| 章节（小说/章回/话数） | 切块段 label（章节标题原文） | 「……」（第52话）      |
| 无结构                 | 片段 N                       | 「……」（片段 7）      |

规则：

- 笔记与生成节点的 `scene` 字段统一填引用单元；无法细分到次级标题时，用切块段 label
- 引文格式固定为 `「……」（引用单元）`，quote-verify 按此解析
- 长剧本切段多属正常：选择闸门（§2）让用户挑选段落，跳过无关段可省 token

## 4. 档案包格式

```text
设定/人物/<名字>/
├── index.md                   # 总索引，唯一机器入口，承载 frontmatter
├── soul.md                    # 核心驱动力、价值观、根本矛盾、弧线判定、情绪处理机制
├── speech_patterns.md         # 句式指纹、称谓、口癖、标志性台词、跨对象语言差异（附引文）
├── behavior_guide.md          # 动作库、社交剧本、If-Then 行为规则
├── relationship_dynamics.md   # 逐关系拆解
├── key_life_events.md         # 编年事件 + 留白区清单
└── limit.md                   # OOC 红线、证据规则（兼作后续生成工作流的写作约束）
```

`index.md` frontmatter：

```yaml
---
shiro_asset: character
depth: full # 目录深卡标记；单文件简卡无此字段
name: 玛奇玛
aliases: [マキマ] # 归并确认后的别名表
role: 对手 # 功能角色
source_work:
  title: 链锯人
  form: script # script | prose
citation: scene # 引用单元方案：scene | chapter | segment
archetype: [支配者, 信徒]
tags: [拆书, 同人还原]
---
```

- 子文件无 frontmatter，固定文件名即契约；正文骨架由提示词模板约束
- 宽容解析：缺子文件不报错，降级显示；`index.md` 缺失才视为档案包损坏
- 深卡不设「可迁移 / 本作设定」两区块——它是还原型档案，「本作」即原作；泛化发布时转换为全局库单文件简卡（V3）
- 格式细则归口 [资产格式](../asset-format.md)，该文档已同步增补深卡形态

## 5. 节点契约

### 5.1 segment-notes（map，LLM·性价比档）

每段一次调用，结构化输出：

```ts
interface SegmentNote {
  segment: string; // 所属切块段 label
  sceneSummaries: { scene: string; summary: string }[];
  charactersOnStage: string[]; // 原文写法，含别名，不归并
  events: { scene: string; what: string; who: string[]; emotion?: string }[];
  relationshipSignals: {
    a: string;
    b: string;
    signal: string;
    scene: string;
  }[];
  mentions: { about: string; by: string; content: string; scene: string }[]; // 幕后提及/评价
}
// form === "prose" 时增加 dialogues: { character: string; line: string; scene: string }[]
// 台词不进摘要、不意译——引用素材必须原文
```

- 解析失败重试 ≤ `NOTES_MAX_RETRY(2)`；仍失败 → 段标记 `notes_failed`，任务继续，最终报告显式列出（禁止静默跳过）
- `mentions` 是幕后角色的关键证据源（角色不在场时的他评）

### 5.2 character-census（确定性统计 + LLM 判定）

- 确定性统计（不靠模型）：每角色台词行数（script form）、出场段数、被提及次数
- LLM 一次调用：别名归并提案（「电次/电次君」→ 电次）、功能角色判定、分层建议（深卡/简卡/忽略）
- **人工确认点 1**：用户确认别名表与深卡名单；确认后按归并名重放确定性统计

### 5.3 evidence-pack（确定性为主，逐角色）

```ts
interface EvidencePack {
  character: string; // 归并后名
  dialogues: { scene: string; line: string }[]; // 台词全录
  actions: { scene: string; text: string }[]; // 角色名邻近 ±2 行的舞台指示/动作行（原始素材，未过滤）
  events: NoteEvent[]; // 时间序
  mentions: Mention[];
  relationshipSignals: RelationshipSignal[];
  sampled: boolean; // dialogues 是否已采样
}
```

- 台词全录：script form 按 `ATTRIBUTION_PATTERNS` 确定性抽取；prose form 取自各段笔记 `dialogues`
- 台词语料 > `DIALOGUE_CORPUS_MAX_LINES(2000)` → 等距采样至 `DIALOGUE_PUSH_MAX_LINES(400)`（保留首尾各 40 行），`sampled: true`；全量语料始终落盘供回查
- 证据包是后续所有生成节点的唯一事实来源；节点内 pull 工具可回读原文段落

### 5.4 生成节点组（LLM·强模型档，逐角色串行子管线）

生成顺序固定，顺序即一致性机制——soul 的结论是后续节点的上下文锚，index 是对全部子文件的压缩，最后生成：

| 序  | 节点                  | push 上下文                                             | 职责                                                                |
| --- | --------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| 1   | soul                  | 事件线 + 情绪点 + 提及、作品梗概（sceneSummaries 合并） | 核心驱动力、价值观、根本矛盾、**弧线判定**（成长/揭示/堕落/无弧线）、**情绪处理机制**（默认状态、压力应对、情绪如何泄露进台词与动作） |
| 2   | speech_patterns       | 台词语料（或采样）+ soul                                | 句式指纹、称谓、口癖、标志性台词、**跨对象语言差异**（对上/对下/对敌的语域切换）；引文必须原文照录 |
| 3   | behavior_guide        | actions + events + soul                                 | 动作库、社交剧本、If-Then 规则                                      |
| 4   | relationship_dynamics | relationshipSignals + mentions（按对象分组）+ soul      | 逐关系拆解                                                          |
| 5   | key_life_events       | events 编年 + sceneSummaries + soul                     | 编年事件锚点 + **留白区清单**（原作未交代处，声明禁止填充）         |
| 6   | limit                 | 1–5 的结论段                                            | OOC 红线、证据规则、卡内禁写事项                                    |
| 7   | index                 | 1–6 全文                                                | 一句话、三条铁律、五条军规、Resource Map——是提炼不是填空            |

模板层输出约束（审核节点按此检查）：

- 性格/行为论断段必须绑定至少一条引文或引用单元，无法支撑的性格词不许写
- 引文格式 `「……」（引用单元）`，机器可解析
- 禁止编造留白区内容；禁止跨素材混入（导入单部作品只拆该作品）

### 5.5 quote-verify（确定性，零 LLM）

1. 解析全部 `「」` 引文及其引用单元
2. 归一化（去空白、全角/半角标点与引号变体统一）后子串匹配，回退顺序：引用单元内 → 相邻单元 → 全文
3. 未命中：所属文件打回重生成 ≤ `QUOTE_REGEN_MAX(1)` 次（附失败原因）；二次失败 → 删除该引文、保留论断，确认界面标黄列出
4. 引用单元本身必须存在于引用单元表，否则同上处理

### 5.6 cross-review（LLM·审核档）

- 卡内一致性：soul 弧线结论 vs behavior/relationship 中的「动摇/变化」描述；index 铁律 vs 子文件结论
- 角色间对偶：A 卡「A 支配 B」与 B 卡「B 信任 A」成对送审，语义冲突打回
- 留白遵守：留白区清单 vs 其他文件的填充性描述
- 输出问题清单 `{ file, claim, conflictWith, suggestion }` → 打回修复 ≤ `CROSS_REVIEW_MAX_ROUNDS(2)` 轮；未解决项随草稿交人工，不阻断

### 5.7 confirm & write（人工确认点 2）

- 逐角色确认：用户审卡（含标黄项）→ 写入 `设定/人物/<名字>/`
- 全部角色处理完后清理草稿目录，任务结束

## 6. 常量

| 常量                        | 值   | 说明                             |
| --------------------------- | ---- | -------------------------------- |
| `ATTRIBUTION_SAMPLE_LINES`  | 1000 | 归属模式抽样行数上限             |
| `ATTRIBUTION_HIT_RATIO`     | 0.6  | 判定 explicit 归属的命中率阈值   |
| `NOTES_MAX_RETRY`           | 2    | 段笔记解析失败重试上限           |
| `DIALOGUE_CORPUS_MAX_LINES` | 2000 | 角色台词语料上限，超过触发采样   |
| `DIALOGUE_PUSH_MAX_LINES`   | 400  | push 给 speech 节点的台词行上限  |
| `ACTION_PROXIMITY_LINES`    | 2    | 动作行抽取的角色名邻近窗口       |
| `QUOTE_REGEN_MAX`           | 1    | 引文回查失败后打回重生成上限     |
| `CROSS_REVIEW_MAX_ROUNDS`   | 2    | 交叉审核修复轮上限               |
| `NOTES_SCHEMA_VERSION`      | `v1` | 笔记结构版本，影响输出结构时递增 |

## 7. 失败语义

| 节点             | 失败             | 处理                                                                        | 阻断 |
| ---------------- | ---------------- | --------------------------------------------------------------------------- | ---- |
| segment-notes    | 解析重试后仍失败 | 段标记 `notes_failed`，报告显式列出；证据包按现有段工作，index 注明覆盖范围 | 否   |
| character-census | 无法判定分层     | 默认全部简卡，用户手动调整                                                  | 否   |
| quote-verify     | 二次回查失败     | 删引文 + 标黄，不删论断                                                     | 否   |
| cross-review     | 两轮修复未过     | 问题清单附草稿交人工                                                        | 否   |

原则：只有「丢正文」类错误阻断任务；质量类问题降级并显式标注，最终由人工确认点兜底。

## 8. 状态、检查点与缓存

- 任务产物落盘 `~/.config/shiro/db/deconstruct/<id>/`：笔记、证据包、各文件草稿均为独立 JSON/MD，每完成一节点即原子写 task.json 快照
- **断点续跑**：管线跳过磁盘上已有产物的阶段（chunks/probe 缓存、notes/<i>.json 逐段、card/<file>.md 逐文件、report.json）；daemon 重启时非终态任务自动续跑，失败任务界面提供「从断点重试」按钮（POST tasks/{id}/retry）
  - 路径为全局而非项目内 `.shiro/`：V1 制作入口在数据库视图（外部导入无项目上下文）；项目内路径留给未来从项目发起的拆解
- 缓存键 = `CHUNKER_VERSION` + `NOTES_SCHEMA_VERSION` + 提示词模板版本 + 输入内容 hash（V1 任务不跨次缓存，缓存能力落地时启用）
- 重跑单个角色不影响其他角色的既有产物
- 确认入库后任务记录保存去向（saved_character_id），草稿目录保留供追溯

## 9. 模型路由

按任务类型路由（daemon 侧新增三个场景，见 [模型接入设计](../backend/model-access.md)）：

| 场景                    | 档位     | 节点          |
| ----------------------- | -------- | ------------- |
| `deconstruct-notes`     | 性价比档 | segment-notes |
| `deconstruct-synthesis` | 强模型档 | 生成节点组    |
| `deconstruct-review`    | 审核档   | cross-review  |

未配置时用默认档案。粗算成本：12 段文本 + 5 个深卡角色 ≈ 12 + 5×9 ≈ 57 次调用，逐角色可并行。

## 10. 渐进落地

- **V1 最小闭环（已实现）**：单角色深卡全链（structure-probe → chunk → notes → 证据包 → 七文件生成 → quote-verify → 保存入库）；各文件厚薄由 §11 验证结果决定，验证无差异的区块维持薄或删。实现偏差：
  - census 未实现——制作表单直接填角色名 + 别名，即人工确认点 1 的替代；证据包为空时报错引导检查名字写法
  - 选择闸门已实现：切块后列出段清单（`segments.json` + POST tasks/{id}/select），用户勾选才开始逐段笔记，全选即全量
  - 进度推送用轮询（前端 1s）；逐段笔记与七文件生成串行执行
  - 产物入全局人物库 `db/人物/<id>/`（目录深卡），未泛化
- **V2**：census 统计与分层、多角色并行子管线、简卡生成、cross-review
- **V3**：泛化发布（深包 → 全局库单文件简卡，提炼可迁移层、去专名）、prose form 对白识别加厚

每级先端到端可用，再加厚。

## 11. 验证方案

目的：确认每类提炼物对剧本角色写作有可分辨的作用。统一判据：**去掉某块，产出是否可分辨地变差**；不可分辨 → 该块降级厚度或删除。验证先于加厚——先证明有用，再做厚。

### 11.1 价值分层（验证优先级依据）

剧本表达角色的通道只有台词与可见动作（无内心独白、无叙述者评价），提炼物按作用分层：

| 层     | 提炼物                                       | 优先级                          |
| ------ | -------------------------------------------- | ------------------------------- |
| 语音层 | 句式指纹、称谓、口癖、跨对象语言差异         | P0：逐行决定台词质量           |
| 行为层 | If-Then 规则、情绪处理机制、社交剧本         | P0–P1：决定场景内反应          |
| 戏剧层 | 驱动力、价值观、根本矛盾、弧线判定、关系动力 | P1：决定场景走向，间接决定台词 |
| 约束层 | OOC 红线、编年事件、留白区                   | P1：防错，写错代价高           |
| 效率件 | index 铁律/军规、Resource Map、引文出处      | P2：需要但不加厚               |

### 11.2 实验

| #   | 实验     | 验证对象 | 做法                                                                                     | 指标                                                                                     |
| --- | -------- | -------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 1   | 台词填空 | 语音层   | 遮住源剧本场景中该角色台词，保留对手台词与场景前提，分别用「整卡 / 去 speech_patterns / 去 soul」补写 | 生成句混入原句做盲选判别（熟悉原作的人或强模型当裁判）；称谓命中率；句长/语气词分布对比 |
| 2   | 反应预测 | 行为层   | 给场景前提（对手做了 X），预测角色反应，比对原作实际                                      | 方向性命中（反应类别一致）                                                               |
| 3   | 越界诱导 | 约束层   | 构造引诱写崩的场景（如令「不可动摇」角色动摇/辩解），带 limit vs 不带                     | 违规率                                                                                   |
| 4   | 穿帮检查 | 一致性   | 生成新场景后问「她此刻知道什么 / 与谁什么关系」，比对编年卡与关系卡                       | 事实错误数                                                                               |

### 11.3 执行说明

- 实验素材直接用源剧本：测的是**还原能力**（卡是否装下了剧本里的角色），不是泛化能力——还原型深卡的目的就是还原
- 两轮验证：实现前用手工卡 + 对应原作文本跑实验 1、3，验证模板设计；V1 产出机器卡后跑同一套实验，验证提炼质量
- 最低成本路径：先跑实验 1 + 3（P0 区间），人工盲评 20–30 条台词即可得出结论
- 结果回灌实现：无差异区块（如动作库在实验 2 无差异）→ V1 该区块维持薄或删除

## 12. 测试要求（确定性节点）

1. structure-probe：冒号引导、名字独行、混合格式、对白内冒号不误报；命中率边界（恰 0.6）
2. evidence-pack：别名归并后台词归集正确；采样确定性（同输入同采样）；邻近窗口抽取
3. quote-verify：归一化匹配（全半角、空白、引号变体）；三级回退顺序；二次失败走删除+标黄路径
4. segment-notes 契约：坏 JSON 重试、`notes_failed` 显式报告、不静默
5. 不变量：证据包 dialogues（script form）每行可在原文定位；引用单元表覆盖全部段 label
