# 自动拆书：切块流程实现规范

本文档定义拆书流水线第 0 阶段「切块」的实现规范。实现者按本文档直接编码。

## 1. 定位与边界

- 职责：把全文文本切分为一组段落，供后续逐段生成结构化笔记。
- 切块是**纯确定性预处理**：
  - 禁止调用 LLM
  - 禁止语义判断（不判断内容重要性、不跳过"不重要"的内容）
  - 相同输入必须产出相同输出（无时间、无随机、无外部状态）
- 实现为纯函数：`(content: string, options?) => ChunkResult`，无 IO，可单元测试。

## 2. 输入与输出契约

```ts
interface SourceSegment {
  label: string;    // 段落标识：章节标题原文，或"片段 N"
  content: string;  // 段落正文（已 trim）
}

interface ChunkStats {
  strategy: "chapter" | "plain";  // 实际走的路径
  segmentCount: number;           // 输出段数
  coveredCharLength: number;      // 实际覆盖的全文末尾位置
  totalCharLength: number;        // 全文字符数
  discardedChapterCount: number;  // 被过滤的超短章节段数
  discardedChapterChars: number;  // 被过滤章节的总字符数
}

interface ChunkResult {
  segments: SourceSegment[];
  stats: ChunkStats;
}
```

要求：

- `coveredCharLength` 必须等于全文长度。**本算法不允许静默丢弃任何正文**；若因段数硬上限无法覆盖全文，必须抛出显式错误（见 §6）。
- 统计字段随切块结果返回，由调用方持久化并在任务详情中展示。

## 3. 常量

| 常量 | 值 | 说明 |
|---|---|---|
| `HEADING_PATTERNS` | 见 §4.1 | 章节标题模式列表（有序、可扩展） |
| `MAX_HEADING_LINE_CHARS` | 80 | 候选标题行的最大长度 |
| `MIN_HEADING_COUNT` | 3 | 认定"有章节结构"的最少标题数 |
| `MIN_CHAPTER_BODY_CHARS` | 120 | 章节段最小正文长度 |
| `TARGET_SEGMENT_COUNT` | 12 | 章节路径的合并目标段数 |
| `MAX_SEGMENT_COUNT` | 24 | 输出段数硬上限（超过则显式失败） |
| `TARGET_SEGMENT_CHARS` | 10_000 | 字符切块的目标段长 |
| `MIN_SEGMENT_CHARS` | 6_000 | 字符切块的边界回退下界 |
| `MAX_SEGMENT_CHARS` | 16_000 | 字符切块的边界搜索上限 |
| `CHUNK_OVERLAP_CHARS` | 400 | 相邻段重叠字符数 |
| `MAX_MERGED_SEGMENT_CHARS` | 48_000 | 章节合并后单段上限 |
| `CHUNKER_VERSION` | 如 `v1` | 切块算法版本号，随算法变更递增 |

## 4. 总流程

```
buildChunks(content):
  1. 统一换行符：\r\n 或 \r → \n
  2. headings = detectHeadings(content)          // §5.1
  3. if headings.length >= MIN_HEADING_COUNT:
         strategy = "chapter"
         segments = splitByChapters(headings)     // §5.2
         segments = mergeSegments(segments)       // §5.3
     else:
         strategy = "plain"
         segments = splitByCharWindows(content)   // §6
  4. if segments.length > MAX_SEGMENT_COUNT:
         throw ChunkOverflowError                 // 显式失败，禁止截断
  5. 返回 { segments, stats }
```

## 5. 章节路径

### 5.1 标题检测

标题模式定义为有序数组，新增文本形态时只追加模式，不改算法：

```ts
const HEADING_PATTERNS = [
  // 中文网文：序章 / 楔子 / 尾声 / 后记 / 番外 / 第X章(节|回|卷|部|集|篇)，X 支持汉字与阿拉伯数字
  /^\s*((序章|楔子|尾声|后记|番外|第[零一二三四五六七八九十百千万两\d]+[章节回卷部集篇])[^\n]{0,40})\s*$/u,
  // 英文章节：chapter 12 / chap. 3
  /^\s*((chapter\s+\d+|chap\.\s*\d+)[^\n]{0,40})\s*$/i,
];
```

逐行扫描，一行计入标题需同时满足：

1. 行 trim 后非空
2. 行长 ≤ `MAX_HEADING_LINE_CHARS(80)`
3. 匹配任一标题模式（整行匹配）

收集 `{ lineIndex, heading }` 列表。

### 5.2 章节切分

- 每个章节段 = 从本标题行开始，到下一个标题行之前（含标题行本身）；最后一个章节段延伸到全文末尾
- `label` = 标题行原文
- 段落 trim 后正文 < `MIN_CHAPTER_BODY_CHARS(120)` → 过滤，并计入 `discardedChapterCount / discardedChapterChars`（不静默）
- 产出章节数 < `MIN_HEADING_COUNT(3)` 时本路径整体放弃（返回前先完成过滤统计，过滤结果不因路径放弃而丢失语义：若最终走 plain 路径，正文不受章节过滤影响）

### 5.3 章节合并

目标：把章节段压缩到约 `TARGET_SEGMENT_COUNT(12)` 段，同时单段不超过 `MAX_MERGED_SEGMENT_CHARS(48_000)`。

```
mergeSegments(chapterSegments):
  if 数量 <= TARGET_SEGMENT_COUNT 且无需拆分:
      直接进入大小检查
  groupSize = ceil(数量 / TARGET_SEGMENT_COUNT)
  按顺序每 groupSize 个连续章节合为一段：
      label   = "首章标题 ~ 末章标题"
      content = 各章正文用 \n\n 连接
  大小检查：
      对每个合并段，若 content 超过 MAX_MERGED_SEGMENT_CHARS：
          在段内按换行边界重新切分为多个子段
          label 规则：沿用首尾章节标题，附加（一）（二）…序号
```

## 6. 字符切块路径（无章节结构）

滑窗推进：

```
start = 0, order = 1
while start < 全文长度:
    end = start + TARGET_SEGMENT_CHARS(10_000)，不超过文末
    boundary = end
    若 end 未到文末:
        candidate = 在 min(start + MAX_SEGMENT_CHARS(16_000), 文末) 处向前找最后一个换行符
        若 candidate > start + MIN_SEGMENT_CHARS(6_000):
            boundary = candidate        // 对齐行边界，避免断句
        // 否则保持 boundary = end，允许硬切（超长单段落场景）
    chunk = text[start, boundary].trim()
    若非空: 收录 { label: "片段 ${order}", content: chunk }；order += 1
    若 boundary 已到文末: 结束
    start = max(boundary - CHUNK_OVERLAP_CHARS(400), start + 1)
```

- 不做末尾截断：全文必须被覆盖，段数超限走 §6 的显式失败
- 目标 1 万字/段；6k 下界与 16k 上界约束边界回退，避免产生过碎的段；400 字重叠缓解跨段上下文断裂

## 7. 失败语义

唯一的失败路径：`segments.length > MAX_SEGMENT_COUNT(24)`。

- 抛出显式错误，错误信息包含：总段数、上限、全文长度、建议（缩小分析范围或启用更大段长配置）
- 禁止以任何形式静默截断、丢弃正文

## 8. 版本与下游衔接

- `CHUNKER_VERSION` 是切块算法的身份标识。任何影响输出的算法变更（常量、正则、切分逻辑）必须递增它
- 下游笔记阶段按段生成结构化笔记并缓存，缓存键必须包含 `CHUNKER_VERSION`——切块方式变化时旧缓存自动失效
- 下游只消费 `(label, content)` 与统计字段，不感知切块内部实现

## 9. 测试要求

实现必须附带覆盖以下场景的单元测试：

1. 章节体文本：正常切分、章节数 ≤12 与 >12 的合并、合并段超限的二次切分
2. 无章节文本：滑窗切分、行边界回退、超长单段落的硬切、400 字重叠的正确性
3. 边界：全文不足一段、恰为 3 个标题、标题行超 80 字、正文含"第X章"字样的长句不被误判
4. 不变量断言：所有段的 content 拼接覆盖全文（允许重叠与 trim 差异）；段数不超上限；stats 与实际结果一致
5. 确定性：同输入两次调用输出完全一致
