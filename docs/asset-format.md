# 资产格式

资产的生成、通用化、引用语义见 [AI写作工具制作思考](./AI写作工具制作思考.md)，存储位置见 [存储设计](./backend/storage.md)。本文只定格式：文件长什么样、字段是什么、机器怎么读。

## 原则

1. **人写的资产是明文 markdown + YAML frontmatter**：与 Obsidian 等写作工具兼容，用户可直接手改
2. **机器回灌的事实数据放 `.shiro/state/`（TOML）**：时间线、信息披露状态、伏笔台账、关系由状态回灌写入（分级提交，部分自动、部分过人工评审），频繁变更、以界面展示为主，不占用正文目录
3. **宽容解析**：缺 frontmatter、缺字段、多余字段都不拒读——按默认值处理，多余字段保留原样；手改坏某个资产不影响其他资产
4. **身份**：项目资产以相对路径为身份（重命名 = 换资产）；全局库条目以文件名为 id，建议 ASCII slug 且不改名——改名导致已应用项目的来源标注失效，失效时降级显示「来源不存在」，不报错
5. **区块约定**：正文用固定标题划分「可迁移 / 本作设定」两区块，机器按标题定位，用户可在区块内自由组织小节

## 角色卡（第一个定稿的格式）

存放：项目内 `设定/人物/<名字>.md`；全局库 `db/人物/<id>.md`（只含可迁移层）。

```markdown
---
shiro_asset: character  # 资产类型标记
name: 沈青梧
archetype: [疯批美人, 高门弃女]   # 原型标签，可多个
role: 对手               # 功能角色：主角 / 对手 / 盟友 / 导师 / …
source: db://characters/fengpi-yituiweijin   # 应用的全局原型（可空）
tags: [女二, 主线]
---

## 可迁移

### 性格核心
（不绑定本书的描写：掌控欲、以退为进、表面柔顺……）

### 动机与目标模式
（她要什么、怕什么、惯用手段——模式层面，不是具体事件）

### 说话风格
（句长、语气、口癖示例——去名化）

### 弧线类型
（堕落 / 救赎 / 镜像对照……类型，不是具体剧情）

## 本作设定

### 身世与背景
（北境侯府嫡女……绑定本世界观）

### 外貌
（本作具体形象）

### 关系
（叙述性描述；结构化关系数据在 .shiro/state/ 中，变更走人工评审）
```

要点：

- **当前状态不进卡**：角色状态、履历由状态回灌写入 `.shiro/state/`，卡保持静态——卡是「她是谁」，状态是「她现在怎样」
- **全局库模板 = 同一格式去掉「本作设定」区块**
- **泛化 / 实例化即两区块间的转换**：泛化 = 提炼可迁移区块并去专名；实例化 = 保留可迁移区块 + 按新世界观生成本作设定区块
- **深卡（目录形态）**：主要角色可用档案包形态 `设定/人物/<名字>/`——`index.md` 承载 frontmatter（`depth: full`、aliases、source_work、citation），soul / speech_patterns / behavior_guide / relationship_dynamics / key_life_events / limit 按固定文件名组织、无 frontmatter；机器只读 index，缺子文件降级不报错。深卡是还原型档案，不设两区块；泛化发布时转换为全局库单文件简卡。结构见 [角色卡提炼工作流](./工具实现/角色卡提炼如何实现.md)

## 其他资产（实现期细化，先定归属）

| 资产 | 位置 | 形态 |
| ---- | ---- | ---- |
| 世界观设定 | `设定/` markdown | 条目化，frontmatter 标类型，正文同样分可迁移 / 本作区块 |
| 节拍模板 | 全局库 `db/` | 三幕、救猫咪等，供卷纲 / 章纲规划引用 |
| 时间线 / 信息披露 / 伏笔台账 | `.shiro/state/*.toml` | 机器写入（分级提交），界面展示与审阅 |
| 关系数据 | `.shiro/state/relationships.toml` | 变更走人工评审 |
| 情绪曲线 | 实现期定（倾向 `.shiro/`：规划期编辑、生成期引用） |
| 图片 | 项目 / 全局库各自目录 | 二进制文件，元数据与描述实现期细化 |

frontmatter 的 `shiro_asset:` 字段是类型标记；未标记的 md 文件按普通文档对待，不强行入库。
